# NextGuard

[English](README.en.md) · Русский

**NextGuard** — устанавливаемый на хост фильтр входящего IPv4-трафика по готовым спискам IP/CIDR. Он загружает и строго проверяет данные, атомарно заменяет один `ipset` и ставит только правила `DROP` в собственных цепочках `iptables`. Разработчик: **@artemkaa_2001**.

> NextGuard не фильтрует IPv6, не меняет его настройки и не создаёт `ip6tables`-правил. IPv6-трафик этим инструментом не защищён. DROP не отправляет RST, REJECT или ICMP-ошибку: удалённая сторона ждёт свой таймаут.

## Модули

| Модуль | Что делает |
|---|---|
| РКН и связанные сканеры | Блокирует записи профильных источников. Некоторые списки содержат авторские наблюдения или широкие сети организаций; совпадение не доказывает принадлежность каждого IP. |
| Базы атакующих, DDoS | Блокирует известные адреса из подходящих баз. Это **не детектор DDoS** и не защита от неизвестного ботнета либо заполнения канала. |
| Остальные сканеры | Блокирует опубликованные IPv4-сети организаций интернет-сканирования. |
| Блокировка ping | Независимо блокирует только входящий IPv4 ICMP echo-request. Другие ICMP и IPv6 не затрагиваются. |

Один адрес в любом источнике включённого модуля блокируется немедленно. Удаление из одного источника сохраняет блокировку, если адрес остался в другом; удаление из всех действующих копий снимает только запрет NextGuard. Оценок, обучения, DPI, WAF, honeypot и автоматических банов по журналам нет.

## Поддержка и установка

Целевая и проверяемая конфигурация — **Ubuntu 24.04 LTS, systemd, iptables (включая штатный backend nft), ipset, Python 3**. Поддержка других ОС не заявляется. Код не требует Docker, аккаунта, открытого управляющего порта или веб-панели.

Сначала изучите код из локальной копии, затем:

```sh
sudo ./install.sh
sudo nextguard
```

Установщик использует `apt` только если отсутствуют `ipset`/`iptables`, сохраняет конфигурацию повторной установки и отказывается затирать чужие `/usr/local/bin/nextguard` или `guard`. Команды доступны через оба имени:

```text
nextguard                 интерактивное меню
nextguard status          модули, источники, поколение и firewall-счётчики
nextguard update          загрузить, проверить и применить сейчас
nextguard logs            последние 100 событий
nextguard --lang en       временно выбрать язык меню
nextguard --help
guard --version
nextguard uninstall
```

Изменение защиты требует root и выдаёт подсказку `sudo`, а не traceback. При запуске через pipe программа открывает `/dev/tty`; без TTY завершается с подсказкой. EOF/Ctrl+C и выход до «Применить» не записывают черновик.

Пример меню (реальный текст программы):

```text
NextGuard — фильтр IPv4 по спискам адресов
Разработчик: @artemkaa_2001
1 Модули  2 Период обновления  3 Журналирование  4 Язык
5 Состояние  6 Обновить сейчас  7 Применить настройки
8 Последние записи  9 Удалить  0 Выход
```

## Обновление и устойчивость

Таймер проверяет источники каждые 30/60 минут. Источник может задавать более редкий минимум. Загрузчик использует TLS, таймаут, предел 32 MiB, `ETag`/`Last-Modified`, понимает 304 и не принимает HTML, битый документ, неверный CIDR, `0.0.0.0/0` или неожиданно пустой ответ. IPv6 пропускается с отдельным счётчиком. При ошибке сохраняется последняя корректная копия именно этого источника; без первой копии статус честно показывает неполное покрытие.

Нормализация объединяет только точно эквивалентные соседние сети и не расширяет множество адресов. Происхождение хранится отдельно. Сначала полностью наполняется временный ipset, затем он меняется с действующим через `swap`; только после успешного firewall-применения меняется ссылка на поколение. Сохраняются два поколения. `flock` исключает конфликт ручного и фонового обновления. На boot `nextguard.service` восстанавливает последнее успешно применённое поколение без Интернета.

## Firewall, UFW и контейнеры

NextGuard не очищает ruleset, не меняет глобальную policy, UFW или чужие правила. Переход в `NEXTGUARD_IN` ставится в начало `INPUT`, поэтому ранний ACCEPT/ESTABLISHED не обходит новый запрет; ответы соединений, начатых сервером, имеют другой source и не фильтруются по адресу назначения. Loopback не совпадёт, кроме явно внесённого источником loopback-адреса (такие источники подключать нельзя).

Для Docker bridge/published ports переход ставится первым в существующую `DOCKER-USER`; Docker не устанавливается и не настраивается. Host mode идёт через INPUT. Это проверено модульными моками, но **реальная Docker/UFW/reboot интеграция в этом окружении не выполнена**. Неподдерживаемый backend без iptables/ipset завершает применение ошибкой. `interfaces` в конфигурации позволяет явно ограничить входные интерфейсы; пустой список означает все интерфейсы.

Reload UFW может удалить добавленный переход: выполните `sudo systemctl restart nextguard`. Автоматическая UFW hook-интеграция намеренно не меняет чужую конфигурацию; сохранение при произвольном UFW reload пока не заявляется.

За CDN/reverse proxy firewall видит сетевого peer, а не HTTP-заголовок с адресом клиента. NextGuard не обещает фильтровать «реального клиента» по `X-Forwarded-For`.

## Журналы

Ограниченный kernel `LOG` (10 сообщений/с, burst 20) имеет префикс NextGuard. `nextguard-log.service` читает только эти сообщения из journald, сопоставляет локальные метаданные активного поколения и пишет локализованный `/var/log/nextguard/events.log`. Повторы группируются на 5 секунд, кэш ограничен 2048 ключами. Встроенная ротация проверяется перед каждой записью: 10 MiB × 5 архивов; logrotate служит дополнительной страховкой. Это выборка событий, **не точный счётчик всех DROP**; точные доступные пакетные счётчики показывает `status`. Сбой логгера не удаляет firewall.

Выбор категорий влияет только на запись, а не DROP. При пересечении событие записывается один раз со всеми активными источниками. Внешних DNS/WHOIS/API-запросов на пакет нет. Файловый лог содержит время с часовым поясом; journald содержит сообщения службы и обработанные события.

## Ping и удаление

Ping-unit идемпотентно владеет только `NEXTGUARD_PING`; list-chain расположена раньше, поэтому совпавший с базой echo-request сохраняет происхождение. Отключение модуля не гарантирует ответ, если ping блокирует провайдер или другой firewall, и ответ на ping не определяет видимость TCP-порта.

`sudo nextguard uninstall` требует `REMOVE`/`УДАЛИТЬ`, отключает только свои units, переходы, цепочки, ipset и собственные symlink. Пакеты и чужой firewall не удаляются; конфигурация, кэш и журналы сохраняются для явного решения администратора. Поэтому удаление не означает «все порты открыты».

## Диагностика и тесты

`status` показывает возраст/ошибку каждой копии, число IPv4 и пропущенных IPv6. HTTP 429 показан как ошибка и старая копия остаётся; минимум обращения не позволяет таймеру обходить лимит. При ошибке применения загруженный кэш остаётся, а следующее `update` повторяет применение даже при неизменных ответах.

```sh
python3 -m unittest discover -v
python3 -m compileall -q nextguard tests
shellcheck install.sh uninstall.sh bin/nextguard bin/ping-control
```

Сетевые тесты следует запускать только в disposable VM/network namespace с отдельным firewall. В комплект не входят внешние базы, секреты или пользовательские логи. См. [SOURCES.md](SOURCES.md), [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md), [TESTING.md](TESTING.md).
